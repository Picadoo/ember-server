## 0. 结论

**F 全部门禁过线，荐总控签 T0″ 过线（F）。** G8 团本 **9/9**（点估全在 ±2 内，最差 R02 4 人 −1.6 [−2.7, −0.6]），T0' A 复现仍是 3/9（与 D313 逐位相同，说明工具改动没动旧结果）。动态 21/21、挂机 21/21、刷图 W30 −0.03，都比 T0' A 更贴 2 槽。E 团本含噪声 9/9，但 **G2 动态 0.5 Q05 −3.0 [−3.3, −2.6] 整段越线 ✗** → E 不过，作废。

**G10 的一个修正（要如实写）：** 设计稿 §0.4 推断团本缺口来自「甲的强化 / 阶级落后护符」。逐人数据显示，到团本池那个时刻（Q07 首通 + 2 周），T0' A 下甲的**阶级落后 0 件、强化差均值只有 −0.05**；真正落后的是**成色和精工**：甲比护符平均低 1.79 档成色、2.21 档精工（成色+精工系数差 +0.116），H 中位 −1.24%。原因是旧规则下新掉的甲从 +0 起，比不过身上已经强化过的旧件，玩家就一直穿着早期成色差的甲（「新件 +0」以成色落后的形式出现）；护符在第二阶段会去精炼 / 锻造，甲不会。F 之所以有效，是因为阶级 / 强化随护符之后，甲**只按成色 / 精工 / 族择优**：成色差缩到 +0.27 档，H 中位缩到 −0.46%。剩下的差距主要是精工（+1.77 档，甲没有锻造途径）。修法本身仍然成立，只是对机理的解释要改。

## 5. 本号工具改动（只 tools，SIX 默认仍 None）

- `p1sim.py` `hp_def()`：`SIX['follow']` ∈ {缺省, `"enh"`, `"all"`}。`"all"`：甲的 tier / enh 取护符，成色 / 精工取甲件；按 Σw = 1 写成 h·(g(护符) + Σ w_a·Δ成色精工)、D = D[护符阶]，甲与护符同成色 / 精工时与 2 槽**逐位相等**。`"enh"`：只有 enh 取护符。缺省走原式。
- `p1sim.py` `invest()`：`"all"` 时升阶 / 强化两个循环都跳过甲；`"enh"` 时只在强化循环跳过甲。`consider_armor()` 未改。
- `p1sim.py` 首通记录：`charm_te` / `armor` 补精工字段（只加字段，不碰随机流）。
- `six_t0.py raid`：每个池只建一次 2 槽 / 6 槽池、评 R01–R03（与 D313 每格单独建池逐位相同，T0' A 已验）；JSON 另存逐人状态（护符 / 刃 / 4 件甲的 T/e/q/f、B、H、M、种子号）；`raidrep` 加「噪声内」判定列 + G10 表。
- `selfcheck.py`：加 2 条（缺省 follow = D313 加权式逐位；`follow:"all"` + 同成色精工甲 = 2 槽 H/M/D/B 逐位，各 3000 组随机）。
- 不改：`p2econ` / `afk.py` / `gear6*.py` 接口；只经 SIX JSON 传 `follow` / `cost`。
