## 读法与结论

- **补丁对数值几乎没有影响。** "按意图"（分身 ×1.5、本体 ×0.8）和现行（分身净 ×1.2）相比：分裂精英击杀用时 0 ～ −2.3%（只有最高投入焚烬 −2.3%、正常推进烬爆 −1.2%，其余 0），通关率、全程用时完全不变（逐局配对，同一批房间）。原因在规则本身：分身 = 一只**普通近战怪 × 0.5 生命**（`EmberRunDirector.splitAdds`：`melee` 角色 × `variety.split.hp`；p1sim 同样实现），一两下就倒；分裂精英的用时几乎全在**本体**和分身出生的 1 秒上。分身伤害 ×1.2 还是 ×1.5 基本感觉不到。
- **所以 B01 是"文字与实现一致"的问题，不是强度问题。** 修好以后「拆分」仍然是第二排里明确的死选项：本体 −20% 让厚甲精英击杀用时 +50%（1.52 → 2.29 s，焚烬 Q07 普通）、炽热精英 +150%（0.49 → 1.26 s），分裂精英本身只比无成长快 7%；破缀在三种精英上都更快。M04 全结构扫描里，带拆分的结构在"可感地被支配"名单里占了大头。
- 建议：按策划裁决改代码（下面的补丁），**同时**单独立项重做拆分的定位（见设计文档 P7「破甲」：只奖励厚甲精英，对其他两种精英减伤害；或把分身生命份额改大让"打分身"成为真事件 —— 后者改的是 `variety.split.hp`，影响所有人，不在本补丁范围）。

   ```diff

    #   dmg_split                        对词缀精英裂出来的分身再 ×

   ...

   -      mods: {dmg_split: 1.50, dmg_affix: 0.80}
   +      mods: {dmg_split: 1.50, dmg_affix_body: 0.80}
   ```
   并把 `version` / `balance_version` 按惯例 +1。文字 good/bad 不用改（现在才和实现一致）。
2. `EmberGrowthService.outMult`：
   ```diff
   -        else if ("split".equals(cls)) r = m.get("dmg_affix") * m.get("dmg_split");
   -        else if ("affix".equals(cls)) r = m.get("dmg_affix");

   ```
   （`Mods.get` 对缺省键返回 1.0，不需要别的改动；建议把这段抽成 `static double classMult(EmberGrowth.Mods m, String cls)` 方便单测。）

4. `EmberGrowthTest` 业务断言（基准伤害 100，审查 B01 验收）：只点拆分 → 普通怪 100、词缀本体 80、分身 150、首领 100；拆分 + 裂身纹 4 档 → 分身 180；拆分 + 猎缀纹 4 档 → 本体 92.8、分身 174；破缀 → 本体 130、分身 130。
