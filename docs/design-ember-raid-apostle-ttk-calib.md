## 2. 现网事实（调研 · 本稿未改）

| 项 | 现网 |
|----|------|
| 人数门 | `plugins/DungeonPlus/dungeon/EmberRaid/option.yml` → `$team-condition{team=true;min=3;max=5;…}` |
| 等级门 | 同文件 `$js-condition`：**有** `%player_is_op%` 豁免；**人数门无 OP 豁免** |
| 进本路径 | `/corerpg enter raid` → `dp start-console`（仍吃 DP condition，含人数门） |
| 使徒 | MM `EmberRaidBoss` Display `团本·终厅使徒` · Health **2000**（spigot 帽注约 melee×0.45） |
| B0.2 债 | 周本 PASS · 深渊 10/12 PASS · **使徒 SKIP**（`enter_refuse: 团本人数 3～5，当前 (1)`） |
| 旁证 | kill-any 测报：3 bot 组队工具链未真正进实例 → Raid live **SKIP**（静态已 PASS） |

**解读：** 卡点是 **可进本**，不是「已测出 TTK 超标要砍 HP」。单人绝对通关时长会偏长，但 **同装同誓约下 L1 满 vs L2 满的 ΔTTK%** 仍可按 B0.2（\|Δ\|&lt;15%）验收；本稿只解锁采集，不宣称「单人 TTK = 正式 3～5 人通关时长」。

## 3. 方案 A / B

| 方案 | 做法摘要 | 利 | 弊 | 本轮 |
|------|----------|----|----|------|
| **A. 单人校准档（临时降门协议）** | 批准后插件岗把 `min=3`→`min=1`（`max=5` 不动）；测试岗单 bot 采使徒 L1/L2 TTK 写入 STATUS；**测毕当日改回 `min=3`**，diff/mtime 入测报 | 改动面 **1 行**；现栈立刻可派；不砍 HP；顺带解 Raid live 进本卡点；ΔTTK 口径与周本/深渊一致 | 测窗内若有真人误进 1 人团本（测服风险，须公告/非开放点）；须纪律还原 | **推荐** |
| **B. 继续诚实 SKIP** | 人数门不动；等 3～5 真人（或稳定 dungeon-team 三 bot）再采 | 零 YAML；正式体验门一字不改 | B0.2 使徒债无限挂；可测性为零；总控无法关账 | 备选 |

### 方案 A · 施工清单（批准后 · 薄）

1. **插件岗（可测服）：** `EmberRaid/option.yml` 与 `server-runtime` 同步树：  
   `$team-condition{…;min=3;…}` → `min=1`（message 可暂改为「校准窗 1～5」或保持原文；**勿**改 max/等级/票）。  
2. **测试岗：** 同装同誓约、无战斗 buff；L1 满 / L2 满各至少 1 轮至使徒倒下；记进本、使徒出现、TTK(s)、结束剩血%、死亡。算 ΔTTK%；\|Δ\|&lt;15% → 可报 B0.2 使徒补测 PASS，否则 **只记数不改数**（另开怪物窗）。  
3. **测毕强制还原：** `min=1` → `min=3`；`cmp` plugins↔server-runtime；测报写「还原前/后」各一行证据。  
4. **表述纪律：** 对外仍「团本 3～5」；本稿结果标 **校准 ΔTTK**，不写「单人正式通关时长达标」。

### 若总控要「永久双轨」而非临时协议（可选升级，非本薄窗默认）

在 A 测通后另批：人数门保持玩家 3～5，仅 OP/`dp start-console` 管理路径可 1 人——须插件或 js 能读队伍人数；**本薄窗不依赖该升级**，避免把可测性绑死新代码。
