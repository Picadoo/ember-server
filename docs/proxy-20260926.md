# Ember 代理接入（2026-09-26 22:47–23:00 CST）

## 拓扑
```
玩家 ──► 0.0.0.0:25565  Waterfall 代理（proxy-runtime/，Java 21，online_mode=false，ip_forward=true）
            ├─► 127.0.0.1:25566  login  （login-runtime/，AuthMe，默认/强制入口）
            └─► 127.0.0.1:25567  play   （server-runtime/，restricted）
```
- 两台后端都是 `server-ip=127.0.0.1`、`spigot.yml bungeecord: true`、`online-mode=false`、`paper.yml bungee-online-mode: false`、`bukkit.yml connection-throttle: -1`（代理后所有连接都来自 127.0.0.1，节流由代理做）。
- 代理的 `priorities: [login]`、`force_default_server: true`：每次新连接都先落在登录服。
- AuthMe `Hooks.bungeecord: true`、`sendPlayerTo: 'play'`：只有 /login 或 /register 成功后才会发 Connect 把人送去 play。未登录时 AuthMe 只放行 /login、/register。
- 代理不装命令模块（`modules.yml: []`，没有 /server、/send、/glist、/find），而且 `disabled_commands` 也列了这些，`permissions.default` 为空。play 设为 `restricted: true`。客户端没法自己切服。
- Waterfall 1.21-615（最后一版，已 EOL）需要 Java 11+，所以新增了 `tools/jdk-21.0.12.1+1`（未入库，Temurin 21）。后端还是 JDK 8。

## 启停
- 全部：`scripts/ember-up.sh`（login → play → proxy）/ `scripts/ember-down.sh`（proxy → play → login）。
- 单独：`proxy-runtime/start.sh|stop.sh`、`server-runtime/…`、`login-runtime/…`。
- 公网穿透（playit/bore 等）应指向 **25565（代理）**，不能指向后端端口。

## UUID
代理处在离线模式，按 `OfflinePlayer:<name>` 生成 UUID，和以前后端直连离线模式完全一样。实测：
- `ProxyT1` 的 UUID 等于离线 UUID；
- `RpgBot` / `NewP33376` 在 usercache 里的 UUID 等于离线 UUID 计算值；
- RpgBot 经代理进服后，CoreRpg MySQL 老数据还在（天梯 深渊最高 7、周本最快 95s）。
