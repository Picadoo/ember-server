> **用途：** 所有 Ember 玩法、场景、副本、挂机区设计稿的交付底稿。复制本文件后填写，不要删除末尾的 UX 否决条。

> **硬规则：** 缺少「站岗表」或「动线」时，稿件必须标为「未完成」，不得报「可验收」。只有菜单可用、没有场景功能锚时，最多标「UI 可用」，不能标「场景完成」。

## 1. 站岗表（功能锚）

每个新功能入口、NPC 服务或场景交互都要有一行。位置必须写清世界和坐标意图，不能只写「大厅」「门口」。右键菜单须给 TrMenu id 及玩家能看到的短话术；副交互没有则写「无」。

**站岗表自检：**

- [ ] 每个功能锚都有明确 NPC id、显示名和站位。
- [ ] 右键入口是 TrMenu / 可点实体路径；玩家路径不要求手打命令。
- [ ] 无 NPC 仅菜单的功能已明确标为「UI 可用」，未宣称「场景完成」。
- [ ] 需要副交互（告示、传送点、商店等）时已写明触发方式和归属。
