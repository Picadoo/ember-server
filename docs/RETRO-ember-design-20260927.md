# RETRO · 余烬设计复盘（2026-09-27）

**状态：仅文档 / 建议**  
**作者岗：** 余烬-策划  
**触发：** 用户要求设计反思；总控转达  
**范围：** 不改数值、不落配置；改的是验收口径与以后交稿习惯

---

## 0. 一句话

我们把「菜单能点开」当成了「玩家能找到玩法」。结果枢纽长期像空城（只有灰烛一个人），地图长期用空岛/共用房顶着玩法验收——**功能通了，场景没站岗，观感欠债被推迟成「以后美化」**。

---

## 1. 枢纽工坊：为何长期只有菜单/告示

### 漏在哪

| 事实 | 后果 |
|------|------|
| 锻炉 / 附魔 / 强化 / 补给 全走 TrMenu + 告示 | 玩家到工坊看不见「人」，不知道找谁 |
| 全服 Ady 长期只有 `ember_guide` 灰烛 | 主线有人，养成/生活无人 |
| 设计稿写「打开 /ember → 锻炉」就算入口闭环 | **把 UI 入口当成场景入口**，漏了「谁站在工坊」 |

根因不是技术做不了 Ady，而是策划交付默认：**菜单有跳转 = 体验完成**。告示被当成主入口，NPC 被当成主线专用装饰。

### 验收标准缺哪一条

以往 hub / 工坊相关验收常见：

- 菜单能开、告示文案对、坐标有方块（熔炉/附魔台）  
- 主线 talk 灰烛 OK  

**缺强制条：**

> **功能锚必须有「站岗 NPC + 右键打开的具体菜单/引导」；仅有 TrMenu/告示 → 场景验收不得标完成。**

P1 广场验收写了「工坊锚、灰烛可见」，仍允许锻炉/附魔/补给无人——说明「有锚点方块」被当成「有人」，标准过松。

四人稿 `docs/design-ember-hub-workshop-npcs.md` 已补（总控批准，P3 后落地）——属于还债，不是一开始就该有的债。

## 2. 地图 P0～P3：是否低估观感

| 问题 | 早期设计态度 | 复盘判断 |
|------|--------------|----------|
| 挂机②～④ y110 空中平台 | 「build 可复现、玩法先通」 | **低估**：每日必进，平面感最伤；不该进「以后美化」筐 |
| 日/周/深渊/灾厄/团本共用小房 + `-40,65,270` | 「脚本先跑，主题后 WE」 | **低估**：换皮同房玩家一眼假；玩法 PASS ≠ 地图 PASS |
| 精英长期 `$setmap ember_weekly` | 「占位可玩」 | **低估**：独立周常却无独立视觉；应用「可玩」顶替「可验收观感」 |
| 深渊竖井只在旧 map-plan 里 | 层数靠 HUD | **低估**：冲层叙事依赖垂直地形，单平面会显得假 |

结论：早期把地图写成 **可选美化**，把脚本写成 **硬验收**——优先级反了。用户明确要多世界实景后，P0～P3 排序才纠正；说明偏好信号来得晚，但设计侧本应更早把「空岛/共用房」标成债务而非常态。

## 3. UX 原则对照：写进稿了吗？强制验收了吗？

用户原则（总控/记忆已有）：

1. 玩家入口优先 **TrMenu**，少打指令  
2. 自定义物走 **NeigeItems ID**  
3. 文案短、少套娃  
4. 地图要实景，不要空平面  

| 原则 | 设计稿里常见写法 | 是否进**强制验收** |
|------|------------------|-------------------|
| TrMenu 优先 | 多数入口写菜单路径 | 半强制：hint 已改菜单话术，但 **场景无人仍 PASS** |
| 不打指令 | 后补禁止 `/dp` `/corerpg` 进玩家 hint | 后补到位；早期 quest/lore 曾教指令 |
| NI ID | 掉落/票设计一般写 NI | 较好；物品岗执行也稳 |
| 实景地图 | 长期「占位可玩」 | **未强制**；直到 multiworld 稿才分「玩法可测 / 地图里程碑」 |

**缺口：** UX 写在「约束/文案」段多，写在「验收 checklist 一票否决」少。以后原则必须落成 **FAIL 条件**，不是开篇装饰句。

## 4. 以后设计交付清单（硬条）

交任何玩法/场景设计稿，缺一条则稿面标 **未完成**，不得报「可验收」：

1. **功能锚站岗表**  
   - 谁（NPC id + 显示名）  
   - 站哪（世界 + 坐标意图）  
   - 右键开什么（TrMenu id / 引导话术）  
   - 副交互（若有）  
   - **无 NPC 仅菜单 → 只能标「UI 可用」，不能标「场景完成」**

2. **副本 / 挂机区视觉与动线**  
   - 独立 map 名或明确分区地形  
   - 入口落点、战斗区掩体/落差、撤离/回枢纽语义（菜单或场景牌，**不教打指令**）  
   - **共用他图且无独立视觉 → 不得进入「地图/内容视觉验收」**（玩法脚本可另测）

3. **UX 强制验收条（文末固定块）**  
   - [ ] 玩家路径零手打指令（管理命令仅管理小节）  
   - [ ] 自定义物均为 NI ID  
   - [ ] 每个新功能锚有站岗 NPC 或等价可点实体  
   - [ ] 地图非空平面占位（或显式列入债务 + 里程碑门槛）

4. **债务显式化**  
   - 占位必须写：`债务：… / 还债里程碑：P? / 在此之前玩法可测、观感不可宣称完成`

## 6. 给总控的要点（可转发用户）

1. **漏 NPC：** 验收只认菜单/告示/方块锚，不认「有人可点」→ 工坊长期空心。  
2. **低估地图：** 空岛与共用房被当成正常占位；精英挂 weekly 拖成观感债。  
3. **UX：** TrMenu/禁指令/NI 多写在约束里，少写成一票否决；地图实景尤甚。  
4. **以后硬条：** 功能锚 = 谁站岗 + 右键开什么；副本 = 独立视觉/动线才可视觉验收。  
5. **纠偏：** 四人稿建议锁死 forge 副交互方案 A、余晶右键必出引导菜单；P4/P5 按独立视觉验收，禁止再「换皮算过」。
