## 3. 方案 A / B

| 方案 | 做法摘要 | 利 | 弊 | 本轮 |
|------|----------|----|----|------|
| **A. 2h 基线采数（默认不动 `afk_caps`）** | 测岗按下方口径跑 **≥1** 次同账号连续挂机（主层 ④，建议 ≥2h 墙钟或等价「达顶后满 105 min」）；写入 STATUS；**窗内不改 YAML**；基线齐后 backlog 标「有基线 · 二档仍待经济窗另批」 | 可测、改动面在测报；解三连挑窗「未选 B0.4」卡点；算数优先；与 B1.3「先采数不砍血」同构 | 需约 2h 测窗；样本单次有波动须在 STATUS 写清 | **推荐** |
| **B. 本轮继续挂** | 维持「无 2h 基线 · 不改数」；不派测窗 | 零测力 | 债名与「何时能开经济」继续脱节；下轮仍占未选位 | 备选 |

### 方案 A · 采数口径（批准后 · 测岗）

#### A1 · 账号与环境

| 项 | 要求 |
|----|------|
| 账号 | **同一**非 op 测号；测前清当日 `afk_*` 日计数（或新号）；测后 `ops=[]` |
| 层 | **主采 ④ 烬原深处**（对齐 softcap 外推主层）；装等满足 Lv≥40，战斗药/strength **禁** |
| 入口 | 玩家路径：枢纽 → 挂机庭 → 选「烬原深处」；管理侧可用 console 等价，**STATUS 须注明** |
| 时长 | 墙钟 **≥ 120 min** 连续在层内战斗（死亡回入口允许，记次数）；或「shard 达顶时刻 T0 + 其后 **≥ 105 min**」二者取严 |
| 禁 | 改 `over_chance`；清日计数中途重置；多号并行充产量；`/ni give` 材料充数 |

#### A2 · 必记指标（写入 STATUS 表）

| # | 指标 | 硬/软 |
|---|------|------|
| 1 | **shard 达顶墙钟**（从开打→日计数首次 ≥150） | 硬 |
| 2 | **2h 末**（或 T0+105min 末）背包/计数：`mat_ember_shard` · `bone_dust` · `core_fragment` · `soul_dust` · 击杀币增量 | 硬 |
| 3 | **分段**：达顶前产量 vs 达顶后产量（至少 shard）；达顶后有效产速 / 达顶前产速比值 | 硬 |
| 4 | 击杀速抽样（达顶前 3 min + 达顶后 3 min，kills/min） | 软 |
| 5 | 死亡次数 · 是否跨层（本窗应 **单层 ④**） | 记录 |

#### A3 · 判定树（关账表述）

```
采数表完整（硬条 1～3）✓
afk_caps / MM / 体力 YAML 测前测后 md5 一致 ✓
→ 基线 PASS；表述「2h 同账号官方产量表已落，非经济改数」
→ backlog：B0.4 标「有基线 · 二档数值仍挂待经济窗」；禁止本窗改 over_chance

比值显著偏离 0.25×（如达顶后仍≈满速或≈0）→ 记异常，查 mmgive/日计数，仍不改数，另开插件排查窗
```

**明确：** 本窗 **不**批准 `over_chance_2` / 改 0.25；经济 B1 须总控凭本基线 **另批**。

1. **存在** `STATUS-ember-afk-b04-2h-baseline.md`，含同账号 · ④ 层 · ≥2h（或 T0+105min）产量表。
