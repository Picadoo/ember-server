**一句话问题：** 名片与近档已让玩家「认得图名与毕业差」，但七图合格重打仍共用同一条 **R1→R2(事件)→R3→Boss** 走廊节拍——要在**不扩 Pack、不重铺地形**前提下，让每图 1～2 个编排旋钮把节奏差做进可感层。

## 1. 玩家感知目标（≤3）

1. **换图有节拍差：** 清房松紧 / 门后喘息 / 事件挂在第几间——至少有一项与邻图可分辨（短句能背：「灰烬事件偏早」「霜封门慢半拍」）。  
2. **仍认得同一骨架：** 仍是 R1–R3+Boss；不靠新词缀、新 kind、新地图包辨识。  
3. **不靠看板吹牛：** 冒险/挑战页可补**一行**节奏短签（可选，依附现有名片格）；玩家不打指令；不抬通关率预算。

## 2. 方案表

### 2.1 方案 M（**荐** · 每图 1～2 编排旋钮 · **仍 9 kind** · 零新 Pack）

在 `ember-v1-runs.yml` 每图增加**可选**编排块（缺省 = 现行行为，保证回滚）：

| 旋钮 | YAML 意向（名可施工微调） | 玩家感知 | 风险 |
|------|---------------------------|----------|------|
| **A · 事件房偏好** | `event.after: r1\|r2\|r3`（现状七图皆 r2）→ 每图改到与名片匹配的一档；或 `event.prefer: [r1,r3]` + 权重（仍单房事件） | 「这图事件来得早/晚」 | 低；不改 `event_rate` / 池 |
| **B · 门延迟** | `rooms.rN.door_delay: 0.0～1.5`（秒；清房→开门） | 「清完有没有半拍喘」 | 低；过长腻 → 上限 1.5s |
| **C · 精英位** | `affix_room: r1\|r2\|r3` 或 `affix_prefer`（词缀精英倾向挂哪间；缺省保持现行随机） | 「这图词缀怪总在前/中/后」 | 低～中；勿与事件同房叠吵时可互斥规则 |
| **D · 波次/房压形状（轻）** | **不**加新波次系统；仅允许每图**重排既有 a/b 表形状**（例：前重后轻 / 中峰）——仍用现有 melee/ranged/heavy/caster 计数，**不**加种、**不**抬全局伤 | 「开局就闷 / 中段才闷」 | **中**——动房压须 p1sim ±2（见 §3.2） |

**首批建议（W1）：**

| 窗 | 做什么 | 不动 |
|----|--------|------|
| **W1a · 事件挂点分图** | 七图 `event.after` 从「全 r2」改成**至少 4 图不同**（例：Q01 r1 / Q02 r2 / Q03 r3 / Q04 r2 / Q05 r1 / Q06 r3 / Q07 r2——终表施工可微调，原则：**邻图不撞同一挂点叙事**） | `event_rate`、9 kind、`event_core` |
| **W1b · 门延迟分图** | 每图选 **0～1** 个门加 `door_delay`（典型 0.6～1.2s）；另图保持 0 | 门碰撞箱/刷点坐标 |
| **W1c · 节奏短签（可选同批）** | 冒险/挑战 lore 在 D283 名片下加半行：`节奏：事件偏早 · 门慢半拍`（纯文案；TrMenu） | 不改 jar 逻辑亦可先文案后逻辑，但**禁止**只改文案不改挂点（纯 lore 薄窗 = 驳回） |

**W2（可同批或续窗）：** 精英位 `affix_room` 分图；若 W1 后真人仍喊「还是一条廊」再开 **D · 房压形状轻排**（单窗最多动 2 图 a/b 形状 + p1sim）。

**期望：** 同骨架下出现**可背的节奏名片**；通关率默认不因 W1a/b 移动（势力事件挂点 / 门喘息不改怪 HP 伤）；若开 W2-D 则走 ±2 门禁。

**荐批：** **批 M（W1a+W1b 必做；W1c 同批；W2 后置或预留）**。

### 2.2 方案 R（轻量图专属脚本钩 · **禁新地图包**）

| 项 | 内容 |
|----|------|
| **做什么** | 在 Director 增加**窄钩**：例 `maps.qXX.hooks.on_room_clear` / `on_door_open` 指向既有 Kether/内建动作表（播短音、短暂减速门、额外提示）——**每图 ≤1 钩**；**禁止**新 DP 地图包、禁止新刷点拓扑、禁止新 kind |
| **回滚** | 钩表空 = 现行；单图钩可配 `enabled: false` 热关 |
| **相对 M** | 表达力更强，但 jar 面更大、易滑向「每图私货脚本」；维护成本高于 YAML 旋钮 |
| **本稿建议** | **默认后置**；仅当批 M 后仍不足、且总控要「音效/演出级」差异时勾 **批 M+R**（R 仍禁新地图包） |

### 2.3 方案 W（**否决默认** · Pack6 或重做七地形）

| 项 | 内容 |
|----|------|
| **提议（不采纳）** | 扩 Pack6（第 10+ 事件 kind / 新词缀）或全面重铺七图地形 / 新地图包，用「新内容」制造差异感 |
| **否决理由** | ① tip / ARCH POLICY：**禁 Pack6、禁全面重做地图包**；扩包边际递减已写明；② 重铺地形工期大、与「同骨架轻差异」目标相反；③ 反馈层（D283）已证明「机制在、编排同」才是痛点——再堆 kind 不解决节拍同构；④ 与 D296「仍 9 kind」口径冲突 |
| **结论** | **默认否决**；批注不提供「批 W」勾选 |
