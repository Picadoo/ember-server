## 0. 一句话结论（给不看数字的人）

- **均匀的「快但脆 / 慢但稳」乘数做不出「明显能感觉到」+「每格通关率 ±3 以内」。** 主线图对强度太敏感：同一个乘数，有的图通关率 +20、有的 −10。
  能同时满足两条的，是**看打法生效**的效果（躲没躲开、怪多不多、血多血少）。所有入选方案都是这一类。
- 第 1 排三选一，改成三种不同打法：**回身斩 = 机动**（躲开预警招后 3 秒 +40%，平时打首领 −8%）、**稳桩 = 站桩**（预警招伤害 −15%，首领普攻 +4%）、
  **踏步回气 → 趁隙 = 压上**（首领每次放预警招后 1.5 秒内对首领 +25%，其余时间 −6%）。在能拿到第 1 排的格子里，三者都在 ±3 以内（个别格 −3.2 / +3.6）。
- 第 3 排：焚烬「连锁燃烧」（杂兵房 −8～−11%，挑战 21/21 格 ±3）可以上；烬爆没找到合格方案；炽愈「救急」可以上（需要先上炽愈削弱 S2）。
- 第 3 排要的点数和价格：**改成第 2 排 1 点、第 3 排 2 点、第 3 排 3000 币（G6）**，不重排、只打团本的玩家第 8 周 99～100% 能点到第 3 排（现在 0% / 94%），两件极品时间线不变。
- **余烬纹、定身纹移出洗练池**（`rollable: false`，和 D165 裂身纹一样）。两次改造（专注纹、迎击纹）都要么不明显、要么超容差。
- **炽愈削弱：生命加成 1.12 → 1.00（只改 yml 一行）。** 炽愈平均通关率从比另两套高 +10 / +18 点降到 +3 / +7 点。团本：随机组队 −0.5～−1.5 点；3 人里有 1 个炽愈的队 −8 点（仍比没有炽愈高 +14 点），R01 不会坏。

### 1.1 细节

- 规则快照：CoreRpg 1.65.3 现行配置（`rules sha256 f23d20ef0ce2779e`，growth v3 = D164 破甲 / D165 裂身纹退池）。候选方案以"替换某一个节点 / 词条 / 套装常数"的方式加进模拟，**和它要替换的现行值配对比较**：同种子、同一批局。
- **强度容差**：7 张图 ×（普通首通，书参考装 r / 挑战 T3+6 c）× 躲避 0.3 / 0.5 / 0.7 = 每套 42 格，每格 3 个种子 × 2,000 局。三套分别跑。目标：每格通关率变化 ≤ ±3pp。
- **只看"够得着"的格（M04 的"真实生效"原则）**：
  - 第 1 排要 1 点，最早在 Q03 首通后拿到，所以 Q01–Q03 的首通格不受影响，算 33 格；
  - 第 3 排要全部天赋点（团本 / 深渊），只出现在挑战 / 团本 / 深渊里，算挑战 21 格；
  - 词条只在 T3 装备上，同样只算挑战 21 格；
  - 套装常数影响所有格，算 42 格。
  42 格全量的结果也列在输出里。
- **体感**：Q04 普通重打（T1+6）、Q07 普通重打（T2+8）、Q07 挑战（T3+6）× 躲避 0.3 / 0.5 / 0.7，每格 3,000 局。每个候选有一个**自己的目标指标**：首领用时 / 杂兵房用时 / 预警招受伤 / 自我回复 / 烬爆次数。达到 ≥ 10% 算明显可感，5–10% 算可能。
- **噪声底线**：同一配置换一组不相交的种子，42 格里最大偏差 +1.7pp，标准差 0.5pp（`out-build-diversity-proposals.md`）。配对比较的噪声更小。
- **留出种子**：入围方案用种子 17 / 19 / 23 复跑容差，体感用种子 777 复跑。
- **团本**：7 个独立玩家池，池聚类 95% 区间（`raidset.py`，同 `raidcomp.py` 的池）。
- **第 6 点门槛**：用真实成本成长模拟（`realcost.py`，300 人 × Q07 后 12 周，d0.5，先装备策略），通过 `P1SIM_WHATIF` 只改天赋点 / 价格。

**本轮最重要的发现（决定了所有方案的形状）：** 主线通关率对强度极其敏感（yml 头注释：+2% 攻击 = Q04 普通 0.5 档 +9 点）。"首领伤害 ×g / 受到首领伤害 ×g"这种看起来中性的交换，在 g = 1.12 时，不同格的通关率会朝**相反方向**摆 ±10～29pp：有的图死在首领、有的死在杂兵，有的首领预警招重、有的普攻重。所以：
- **均匀的"快但脆 / 慢但稳"乘数做不到"≥ 10% 可感 + 每格 ±3"**。这一类全部淘汰（A / B / 清场 / 破阵 / 专注纹）。
- 能同时满足两条的，是**条件型**效果：收益取决于玩家怎么打（躲没躲开、怪多不多、血多血少）。效果只在那种打法下 ≥ 10%，平均下来强度不变。

`win_*` 是 NEW 键（Java）：
- `EmberGrowth`：`win_secs` 加进 `ADD`（取最大，同 `dodge_secs` 的写法）；`win_dmg` / `win_out` 是乘数。
- `EmberGrowthService`：新增 `Map<UUID, Long> winUntil`；`onWindow(Player p)`：`if (m.get("win_secs") > 0) winUntil.put(uuid, now + secs*1000)`；
  `EmberRunDirector` 预警招落下处（`g.onTeleHit(p)` 那个循环和 `g.onDodge(p)` 那个循环）对**被打中的和躲开的**都调用 `g.onWindow(p)`。
- `outMult`：`if ("boss".equals(cls) && m.has("win_dmg")) r *= now < winUntil ? m.get("win_dmg") : m.get("win_out");`（打首领的所有伤害，含套装事件，和 `dodge_dmg` 一样）。
- 测试：窗口内首领 ×1.25、窗口外 ×0.94、非首领 ×1.0；被打中也开窗口；`tools/p1sim/javacheck` 加一条对照（p1sim.dmult 已实现）。
- 已点「踏步回气」的人自动变成「趁隙」（id 不变，不用重置）；`EmberGrowth.CN` 加 `win_dmg` 的中文名。
