# DESIGN — P1 挂机庭（D177 · CoreRpg 1.65.9）

日期：2026-10-04 · 作者：afk-p1 执行者 · 研究：`RESEARCH-ember-afk-2026-10-04.md`
业主（17:56）：「挂机这部分怎么样了？现在很多人没时间，挂机服很火。」——业主授权自行决定，下面全部是定稿（Stage 1 已上线）。

## 0. 一句话
**复用旧 `ember_afk` 世界做 P1「挂机庭」**：四层按主线首通开放（Q01 / Q03 / Q05 / Q07），人在挂机庭里每 10 分钟自动结算一轮
**账号绑定的余烬币 + 余烬经验**，下线时间按 1/4 折算；每天最多 12 轮。**满一天挂机 ≤ 一次通关的基础币和经验**，
不给碎片、核心、印记、装备——装备和材料仍然只从主线本来。

## 1. 为什么这样做（对照研究）
| 决定 | 参考 | 研究 § |
|---|---|---|
| 收益按已首通的最高主线层定档 | AFK Arena 挂机收益按最高关卡 | 1.3 |
| 每日 120 计时分钟上限（12 轮 × 10 分钟），封顶后为零 | 冒险岛 M 每日 120 分钟；RO 每日 150 分钟；挂机池每日上限 | 1.4 / 1.5 / 1.7 |
| 离线按 1/4 折算、每天最多 6 轮 | WoW 野外下线 1/4 休息速率；AFK Arena 宝箱封顶 | 1.1 / 1.3 |
| 进区域就计时、零操作、不必打怪 | 传奇泡点；国内挂机池 | 1.6 / 1.7 |
| 只给账号内货币，不给可交易材料 | MC 挂机池惯例；RO 针对多开压时长 | 1.5 / 1.7 |
| 先记账（唯一键）后发放 | IdlePool 唯一结算号 + 暂存箱 | 1.7 |
| 收益远低于主动打本 | 泡点低于打怪；RO / WoW 休息只是追赶 | 1.1 / 1.5 / 1.6 |

## 2. 改动 D63 的那条规则

  四层按钮（未开放显示屏障 + 开放条件，点了跳到冒险页）、今日进度（PAPI 实时）、回枢纽、返回主菜单。
  旧 `ember_afk.yml` 只留给旧枢纽。
- PAPI：`%corerpg_p1_afk_t1..t4%`（1 = 已开放）、`_tier`、`_rate`、`_today`、`_next`、`_rounds`、`_on`。

## 4. 计时规则
- **在线**：每 60 秒（服务器计时器）检查挂机庭里的玩家；活着、已首通 Q01、今日未满 → 计 1 分钟；满 `round_minutes`（10）结算一轮，自动到账，聊天提示。
  离开挂机庭停表，已攒的分钟当天保留。
- **离线**：下线时记下分钟戳；下次上线时 `离线分钟 ÷ 4 ÷ 10` 轮，**每天最多 6 轮**（= 4 小时离线），按上线时已解锁的最高层发。
  分钟戳上线即消费——反复上下线拿不到第二次。服务器重启：`onDisable` 给所有在线玩家补记下线戳（Bukkit 关服时退出事件在插件停用之后）。
  崩溃（没有 onDisable）= 那段时间不计，**只会少不会多**。
- **每日**：在线 + 离线合计 `daily_rounds`（12）轮，体力日 0 点重置（`DailyService.today()`）。封顶后提示「今日已满，想更快变强还是打主线本」。
- 数值都在 `plugins/CoreRpg/ember-v1.yml` 的 `afk:`（**config.yml 一个键都没改**）：

```yaml
afk:
  enabled: true
  world: ember_afk
  round_minutes: 10
  daily_rounds: 12
  offline_ratio: 4
  offline_rounds: 6
  legacy_payouts: false
  tiers:
    - {n: 1, name: 灰坡, requires: q01, coin: 8, xp: 3}
    - {n: 2, name: 荒原, requires: q03, coin: 12, xp: 5}
    - {n: 3, name: 焦土, requires: q05, coin: 16, xp: 6}
    - {n: 4, name: 烬原深处, requires: q07, coin: 25, xp: 10}
legacy_auction: false
```

## 5. 挂机 vs 主动（为什么不会压过打本）
**挂机占收入的比例（满额挂机 + 每天 3 次通关）**：余烬币 T1 8%（96 / 1146）→ T4 22%（300 / 1350）；经验 T1 9% → T4 25%；
碎片 / 核心 / 印记 / 装备 **0%**。

一个主动日（3 次通关 + 每日委托）≈ **1050 币、84 碎片、7.5 核心、360 经验 + 3 次装备掉落 + 3 枚印记**。

| | 余烬币 / 天 | 经验 / 天 | 碎片 / 核心 / 印记 / 装备 |
|---|---:|---:|---|
| 主动 3 次通关 | ≈ 1050 | ≈ 360 | 有（唯一来源） |
| 挂机满额 T1（Q01 后） | 96 | 36 | 无 |
| 挂机满额 T4（Q07 后） | 300 | 120 | 无 |
| 一次通关的基础 | 300 | 120 | 有 |

- 满一天挂机（2 小时在线计时，或 4 小时离线 + 1 小时在线）**不超过一次通关的基础币和经验**，T4 才追平，T1–T3 都更少。
- 挂机给的东西只能让人**更早攒够强化 / 锻造的币**，变强仍要材料和装备——只有打本有。
- 忙碌玩家（每天 1 次通关）+ 满额挂机，到 Q07 首通仍远慢于每天 3 次通关、不挂机的活跃玩家（§7）。

## 6. 漏洞审查（exploit review）
| 风险 | 做法 | 结论 |
|---|---|---|
| **多开 / 小号刷**（挂一堆号） | 挂机只给**账号绑定**的余烬币 + 经验；余烬币在 P1 没有转账途径（邮件发送需要 `corerpg.mail.send`，玩家没有；P1 无交易，D73）。旧寄售 `/corerpg ah` 是唯一能跨号转币 / 核心的命令路径 → **P1 下对玩家关闭**（`legacy_auction: false`，管理员与旧模式不变）。挂机不发任何可丢弃的物品。 | 小号挂出来的币只能小号自己用，养号不产出能给主号的东西。**不做 IP 限制**：同 IP 的家庭 / 网吧会被误伤，而收益不可转移，限 IP 没有收益。 |
| **挂机机 / 宏** | 不需要打怪、不需要动；收益只看「人在挂机庭的分钟」，并且每天 12 轮封顶。挂机机最多拿到和一个普通忙碌玩家完全一样的封顶值。 | 不做动作检测（RO / AFKRoom 那套）：封顶后为零，检测没有收益只有误伤。`player-idle-timeout=0` 保持。 |
| **离线累积刷** | 离线 1/4、每天最多 6 轮、算在 12 轮之内；下线戳上线即消费，反复上下线拿不到；跨天离线也只按上线当天的 6 轮封顶（不会一次补好几天）。时间全用服务器时钟，客户端改不了。崩溃不补。 | 离线最多 = 半天上限，按上线时最高层。|
| **在线 + 离线叠加** | 在线只在玩家在线时计；离线只算下线到上线的间隔；两者共用 12 轮。 | 没有重叠窗口。 |
| **旧挂机怪的材料漏洞（已有）** | 旧怪掉的 `mat_ember_shard` / `bone_dust` / `core_fragment` 与 P1 主线本是**同一批 NI 材料**，旧上限每天 150 碎片（主动日约 84）且命令 `/corerpg afk` 默认可达 → **P1 下 `mmgive/mmxp`、击杀币、击杀经验在挂机庭全部关闭**。实测（1.65.9）控制台 `corerpg mmgive <在挂机庭的玩家> mat_ember_shard 5` 不发。 | 漏洞关闭。旧模式（P1 关闭时）行为不变。 |
| **重复发放 / 刷单** | 先推进当日轮数计数并落盘（`flushMutation`），再写账本行 `p1afk-<日>/c<k>`、`x<k>`（唯一键，PENDING → 由现有 `EmberRunService.deliver` 发放）；同一键重复写入不生效。 | 崩溃最多丢一轮，**不会多发**。没有新的物品路径，`persist-roundtrip.sh` 不需要重跑（资产路径未改）。 |
| **挂机庭里打本 / 进本刷** | 主线本实例里不能 `/corerpg afk`；挂机庭不是副本世界，主线本的结算与挂机互不相通。 | — |
| **等级跳层** | P1 下层只看首通标记（`progressFlag`），旧等级门槛与升级提示在 P1 关闭。 | — |
| 广义遗留（**本文不修**） | 其它 D63 隐藏的旧系统仍有命令入口，可能也发 P1 同名材料（旧日常 / 旧精英等）。普通世界 `world` 的击杀币仍按旧规则。 | 记为后续：「D63 旧命令入口全面审查」。 |

## 7. p1sim 检查（只用离线模拟，「在范围内」即可）
工具：`tools/p1sim/afk.py`（包装 `Player.bounty`，每个体力日按玩家已解锁的最高层发 `share × 每日上限` 的币和经验；
`share 1.0` = 每天都挂满，是上界）。规则 sha `30247b0d086df8fd`（balance_version 31）；1.65.9 再用 balance_version 33 复跑一次（D178 只改挑战周规则，不影响）。

### 7.1 动态首通 21 格（Q01–Q07 × 躲避 0.3 / 0.5 / 0.7，±2pp）
| 运行 | 结果 | 最大 |差| |
|---|---|---|
| 800 人 · share 1.0 | **21/21** | 1.9 pp（0.3 Q06） |
| 1600 人独立种子 · share 1.0 | **21/21** | 1.9 pp（0.5 Q07） |
| 800 人 · share 0.5 | **21/21** | 1.1 pp |
| 800 人 · share 1.0 · balance_version 33（1.65.9 规则） | 20/21 | 2.1 pp（0.3 Q06，刚过线） |
| 1600 人独立种子 · share 1.0 · balance_version 33 | **21/21** | 1.9 pp（同格 0.3 Q06 为 +1.5） |

- 首通天数（中位 / P90）：躲避 0.3 的 Q07 26 → 24 天、36 → 33 天；躲避 0.5 / 0.7 不变（8 / 3 天）。
- 等级：躲避 0.3 的 Q07 首通时 Lv 32 → 35（经验多了），0.5 为 22 → 24，0.7 不变——都在格子容差内。
- 被否的更高方案：每日 150 / 200 / 250 / 300 币（800 人 20/21，0.3 Q04 2.3pp 超）→ 降到现行 96 / 144 / 192 / 300。

### 7.2 忙碌玩家（400 人，每天 1 次通关 + 满额挂机 vs 每天 3 次通关）
| Q07 首通中位天 | 忙碌 无挂机 | 忙碌 + 挂机 | 活跃 无挂机 | 活跃 + 挂机 |
|---|---:|---:|---:|---:|
| 躲避 0.3 | 77 | 61 | 26 | 24 |
| 躲避 0.5 | 23 | 21 | 8 | 8 |
| 躲避 0.7 | 9 | 9 | 3 | 3 |

挂机让忙碌玩家快了 0–16 天（主要是低躲避玩家，靠币把强化提前），**但永远远慢于活跃玩家**——挂机值得做，不会替代打本。

### 7.3 两件极品时间线 W30（p2econ，300 人 × 12 周，躲避 0.5，深渊 + 团本 + 周目标；±0.5 周）
| 运行 | 最早 W30（候选策略最早） | 差 | 各路线差（深渊 / 深渊+周目标 / 团本+周目标 / 无轮换 / P2-1 轮换 / 轮换+团本） |
|---|---:|---:|---|
| 基线（无挂机） | 4.86 | — | 4.86 / 5.36 / 6.50 / 7.00 / 7.29 / 7.00 |
| share 0.5（每天挂一半，≈ 只靠离线 6 轮） | 4.62 | **−0.24 ✔** | −0.24 / −0.44 / −0.50 / 0 / −0.29 / 0 |
| share 1.0（上界：每人每天 12 轮挂满 12 周） | 4.30 | **−0.56 ✘（超 ±0.5 0.06 周）** | −0.56 / −0.78 / −0.75 / −0.50 / −0.69 / −0.14 |

- 结论：**21 格在范围内；W30 在现实挂机量（share 0.5）在范围内，在上界（share 1.0）略超**。原因是挂机币让强化 / 锻造的币更早够，两件极品早到。
  （C / H 两档经验不变，同时能看出经验对 W30 有没有影响。）
- **决定（Stage 1.1，下一步，只改配置）**：把每轮余烬币降到 W30 上界也在 ±0.5 内的最高一档，经验不动。
  候选已在跑（balance_version 33 同规则基线 + 两档，share 1.0）：C = 每日 60 / 84 / 120 / 180 币（每轮 5 / 7 / 10 / 15），

  对比命令 `python3 tools/p1sim/growthrun.py weeks /tmp/afk/p2b-base.md /tmp/afk/p2b-C.md /tmp/afk/p2b-H.md`。
  选定后：改两份 `ember-v1.yml afk.tiers`、`ember_p1_afk.yml` 文案、`EmberAfkServiceTest` 期望值、`afk.py TIERS`，
  `corerpg reload` + `trmenu reload`（不用重启），并复跑 `afk.py dyn`。目前没有真实玩家，线上暂按 Stage 1 数值运行不造成存量问题。
