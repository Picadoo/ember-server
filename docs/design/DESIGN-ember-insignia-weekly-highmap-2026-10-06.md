## 3. 三个候选（R1）

### 选项 A — 残响「回声最高图」（echo → highest cleared）

- **动作：** S18 领奖时，徽记发给「本人已首通的最高签名图」（与 S23 `EmberSignService.sigMap` 同规则），而不是固定 echo 厅所属图（今天 q01–q04）。
- **周上限：** 保持现网 `p4_echo_claim` = 3 次/周、每次数量仍读 economy `S18.insignia`（现 2）——**本稿不改这些数**。
- **效果预期（定性）：** 毕业玩家每周最多 3×现网每次数 的 **Q07（或当前最高图）** 徽记；低图残响堆积减速；Q05–Q06 在「最高=该图」窗口也能吃到。
- **风险：** 推图途中最高图变化 → 早期仍进低图；需确认 UI/文案「残响厅」与发放图解耦是否可接受。
- **sim：** `insignia.py` what-if：`ECHO` 发放目标改为 `highest cleared in MAPS`；重跑 W30；看 Q01–Q04 结余、Q05–Q06、Q07、调律次数、两槽 Q07%。

### 选项 B — 补 Q05–Q07 残响厅（echo halls）

- **动作：** 在现有 echo_q01–q04 之外，增加 echo_q05–q07（或合并入口），仍共用（或分组）周领奖帽。
- **周上限：** 若共用 `p4_echo_claim`，总量不变、只改可领图集合；若分组，必须先定「高图组周帽」并 **只在 sim 里试**，不得直接写进 live。
- **效果预期：** 玩家可主动选高图厅；低图堆积不一定下降（低图厅仍可领）。
- **风险：** 地图/NPC/UI 工作量大；分组周帽容易超发。
- **sim：** 扩展 `ECHO['maps']`；扫「共用 3」vs「高图组另帽 N」；对照调律与 Q07%。

### 选项 C — 有帽的低→高兑换（capped swap）

- **动作：** 新消耗（建议登记为新 `Cxx`，勿塞进 C12/C13）：用 N 枚低图徽记换 1 枚指定高图徽记；**每周兑换次数或兑换枚数有上限**。
- **周上限 / 比率：** **本稿不给 N 或周帽数字**；由 sim 扫参（例如目标：熟练档 W12 两槽 Q07% 明显抬升，且 Q01–Q04 结余下降但不归零）。
- **效果预期：** 直接消化死库存；玩家可控；与「分图不可互换」的现规则需文案说明「这是官方兑换口」。
- **风险：** 比率过松 → 高图签名通胀；过紧 → 无感。需防与烙印/调律抢同一桶。
- **sim：** 新 sink + weekly counter；策略：优先换当前 want() 的最高图；扫 N∈{…}、周帽∈{…}（仅 sim）。

**不推荐（D222 已否）：** 挑战/深渊发徽记；无限跨图；无帽兑换。
