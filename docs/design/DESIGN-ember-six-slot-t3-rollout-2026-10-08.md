### 1.2 开关顺序（必须遵守 OPS §1.2 / §1.3）

**开（同一次编辑、一次 `/corerpg reload`）：**

```yaml
gear:
  six_slot:
    enabled: true
    migrate: true
```

- **禁止**只开 `enabled`、不开 `migrate`：未迁移号会按空甲位算，H/D 低于迁移前（OPS §1.2 第 2 步；T2 已观察到过渡态混原版甲 H 偏低）。
- 前置检查（OPS §1.2 第 1 步）：jar 含 D319–D321 能力；NI 甲模板已加载；菜单 `ember_p1_armor` 已上；`storage: mysql`；`/corerpg storage` ping 绿、`storage guard` = 未拦截；近期无 upsert / schema 失败日志。
- 核对：`/corerpg p1 armor status <在线号>` 末尾 `enabled=… migrate=…`。

**关：**

| 目的 | 操作（OPS §1.3 / §7） | 之后状态 |
|------|----------------------|----------|
| 只停新迁移 | `migrate: false` → reload | 已迁移号照常；待领可领；未迁移号若 `enabled` 仍开则按空甲位算 → **迁移窗口未结束前不要长期停在此态** |
| 全部回滚 | **先**清空未决 journal（枢纽或 `armor mig` 续上至 `journal=false`），再两键都 `false` → reload | 2 槽公式；已发甲变惰性；**待领仍可领**；DB 行不删；invsnap 守卫仍生效 |

**回滚一句话：** 先续完 journal → 两开关同关 → **不回退 jar 也可**（功能关死）；若必须回退到 1.65.97，OP 须人工遵守 OPS §6「不恢复迁移前快照」；**DB 行与 `p1-six/*.yml` 一律保留**；待领由玩家自领（开关关也可）。

## §2 迁移窗口

### 2.1 谁迁移

| 方式 | 条件 | 说明 |
|------|------|------|
| **进枢纽自动**（主路径） | `migrate` 开；进服第 120 tick / 换世界回枢纽第 40 tick；不在副本、不在挂机庭、活着、非旁观 | OPS §1.2 第 3 步；全员默认走这条 |
| **管理命令** | `/corerpg p1 armor mig <玩家>`（`corerpg.admin`）；要求 `migrate` 开且目标在枢纽 | 卡住号、白名单催迁、演练续上 |
| **不迁移** | 新号从未有过护符 / 未进枢纽；或 `migrate` 关 | 新号靠起步包 + Q01 首通 4 件（T1 规格），不走老号迁移 |

范围：真人号与测试 / 管理号同一路径（T1 §3.2）。

### 2.2 幂等与失败

- 完成标记 **`p1_six_mig: 1`** 与 `done_at`、`pieces` **同次写入**（OPS §3.3 / §7.1）；重复进枢纽 → `ALREADY`，不重发。
- **DB_PENDING**：四件甲 DB 回执未齐前不置完成标记；journal / 换装标签保留；日志带 `DB_PENDING`（OPS §3.3）。长时间停住 → 按 OPS §3.1 / §3.2 查 DB。
- **中途关服 / kill：** journal 未决 → 下次回枢纽自动 `ROLLED_FORWARD`；禁止手删 `ember_six_m_*`（OPS §2，删了会丢原物）。
- **自检不等：** 发放后 H/D 与迁移前不逐位 → 撤回本次、不置标记、告警 OP（T1 §3.2；T2 H1 已验逐位）。
- **DB 行自愈：** 已完成号进服 / ALREADY 时对 `pieces` 做 INSERT IGNORE（OPS §3.4）；不复活 retired。

### 2.3 待领（对齐 D320 / T1 §5.4-1）

- 迁移时甲位**一切**（原版、他人 P1、**本人 P1 甲**）→ 每人 `p1-six/<uuid>.yml` 的 **stash 待领**，再穿迁移甲。
- **开关关也可领**（OPS §7.2）：`enabled=false migrate=false` 下护甲页仍有待领入口；防连点 / 幂等 / 存档顺序与开时相同。
- 守恒：`待领物品数（迁移刚完成时）= 迁移前甲位物品数`；领取中途关服 / 背包满 / 重复点击不丢不复制（T1-4 / T1-6）。
- audit：待领内 active uid = `ACTIVE_IN_STASH`，**禁止** `audit restore`（OPS §4.1）；真正 `ACTIVE_NOT_HELD` 才考虑 restore。

### 2.4 玩家可见文案（短 · TrMenu · 无命令教学）

入口：`/ember` → 装备 → 护甲页。文案岗可改字，口径如下（示例）：

| 时机 | 示例 |
|------|------|
| 迁移刚完成 | `§7护甲位原来的 %n% 件已存好 · §e点这里领取`（T1 §5.4-1） |
| 待领入口 | `§e领取原护甲（%n% 件）` |
| 开关关且无待领 | `§7护甲功能尚未开放` |
| 开关关但有待领 | 同上 + 待领入口仍可点 |
| 工坊手持甲 | `§7护甲随护符成长；成色 / 精工看掉落`（K0） |

**不出现** `/corerpg` 教学、战力分、排行。菜单代发内部命令（`claim` / `equip` / `all` 等），与 OPS §8 一致。

### 2.5 运维观察清单（迁移窗口内）

按 OPS §3.1 定时：`/corerpg storage`、`storage guard`、日志无 upsert 失败、抽查 `armor status` / `audit`。出现 OPS §9 告警按表处理；DBDOWN → **立即 `migrate=false` + reload**（OPS §3.2）。

### 5.3 中止条件（触发即停扩 / 关 migrate，必要时两开关全关）

1. 审计出现**非预期**资产差异（丢失、同 uid 有效 >1、跨服复制）。
2. 迁移后 H/D **不**逐位相等且自检未撤回成功。
3. DBDOWN 持续或大面积 DB_PENDING / 误标完成。
4. 结算掉甲或掉落分解路径失败（§4.2）。
5. 代理路径下迁移无法完成或产生复制（§4.1）。
6. 未决 journal 在关 migrate 前无法清空却已关开关（违反 OPS §7.3）— 视为事故，立即重开 migrate 续上。
