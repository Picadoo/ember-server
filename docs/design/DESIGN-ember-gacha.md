# 余烬服 · 外观扭蛋 CoreGacha 设计

**日期：** 2026-10-04（Asia/Shanghai）
**状态：** 已定稿，按这份实现（插件 `CoreGacha/`，参数 `plugins/CoreGacha/gacha.yml` + `config.yml`）
**红线来源：** `docs/design/DESIGN-ember-economy-monetization.md` §5.1「抽奖箱出战力 — 禁止，可用外观扭蛋」、§9「无上限抽奖不做」、§2「战力不来自钱包」。

---

## 0. 一句话

一个**只出外观**的扭蛋：称号、聊天徽记、光环粒子、宠物、烟火特效，以及 CoreRpg 外观商店里已有的称号颜色 / 足迹 / 名牌标记 / 辉光 / 动效。**零属性、零材料、零币**；只用游戏里挣来的东西抽；**没有任何真钱入口**（不收晶钻、不卖券、不接充值）。

## 1. 红线（实现里写死，配置改不掉）

| # | 规则 | 怎么保证 |
|---|------|----------|
| 1 | 奖池里只有外观 | 物品种类只有 `badge` `tag` `aura` `pet` `show` `corerpg`（后者只接受 CoreRpg `EmberCosmetics.SHOP` 里 `shop()==true` 的条目，启动时逐条校验，不在商店表里的直接禁用并告警） |
| 2 | 不出战力、材料、余烬币、印记、碎片、门票 | 奖励没有这些类型；光屑只能换本池外观，不能换别的 |
| 3 | 不用真钱 | 货币只有扭蛋券（游戏里得）和光屑（重复返还）。不读 `ember_crystal_cash`，不接 `cash.yml` |
| 4 | 不无上限 | 每人每天最多 50 抽（`daily_pull_cap`），换券每天最多 5 张 |
| 5 | 活动限定的东西不进扭蛋 | 国庆活动称号「盛世烟火」、红金烟火足迹、盛世烟火符只能活动里拿（D139），扭蛋不碰 |
| 6 | 宠物只是跟随的装饰 | 无 AI、无碰撞、无敌、不掉落、只在主城显示；光环 / 宠物 / 烟火在副本世界（`dungeon_*`）里不显示 |

## 2. 货币

### 2.1 扭蛋券（每抽 1 张）

钱包在 MySQL（`gacha_wallet.tickets`）。也有实物「扭蛋券」（NeigeItems `ember_gacha_ticket`，按 NI ID 认，不认显示名），右键或 `/gacha redeem` 存进钱包，给以后的副本掉落 / 邮件 / 活动发券用。

| 来源 | 数量 | 说明 |
|------|------|------|
| 首次打开扭蛋 | 5（一次） | 见面礼，够体验一次单抽 + 看动画 |
| 当日活跃在线 30 分钟 / 90 分钟 | 各 1 | 「活跃」= 这一分钟里走动过；挂机区 `ember_afk` 不算 |
| 当日主线结算 ≥1 局 / ≥3 局（读 CoreRpg 每日委托计数 `p2_bounty`） | 各 1 | 只读，不改 CoreRpg |
| 余烬币兑换 | 1200 币 → 1 张 | 后期币堆积的花币出口（交接文档 §7「后期币堆积」） |
| 余烬徽兑换 | 20 徽 → 1 张 | 1 徽 = 50 币，同价 |
| 兑换上限 | 两种合计 5 张 / 天 | |

免费玩家每天约 4 张（≈ 28 张 / 周），满兑换约 9 张 / 天。按综合传说率 1/54.6，免费约两周一件传说，满兑换约 6 天一件。

### 2.2 光屑（重复返还，炉石式）

抽到已拥有的外观 → 返还光屑；光屑可**直接兑换池里任意一件**（所有开放中的池 + 常驻池，含已转常驻的往期限定）。

| 品质 | 重复返还 | 兑换价 | 返还 / 兑换 |
|------|---------|--------|-------------|
| 传说 | 300 | 1800 | 1/6 |
| 史诗 | 80 | 480 | 1/6 |
| 稀有 | 20 | 120 | 1/6 |
| 普通 | 5 | 40 | 1/8 |

限定池结束时，没用掉的火花点按 1 点 = 1 光屑折成光屑（进服或打开扭蛋时自动结算，记账）。

## 3. 品质与概率（公示）

### 3.1 基础概率（每一抽）

| 品质 | 颜色 | 基础概率 |
|------|------|----------|
| 传说 | §6 金 | 0.6% |
| 史诗 | §d 紫 | 5.1% |
| 稀有 | §b 蓝 | 14.3% |
| 普通 | §7 灰 | 80.0%（= 100% − 上面三项） |

### 3.2 保底（原神式软保底 + 硬保底）

- 记「距上次传说已抽 k 抽」（这一抽算第 k 抽）。
- 第 1–60 抽：传说概率固定 0.6%。
- 第 61–79 抽：每多一抽 +4%：第 k 抽传说概率 = 0.6% + 4% × (k − 60)（第 61 抽 4.6%，第 70 抽 40.6%，第 79 抽 76.6%）。
- 第 80 抽：必出传说（硬保底，永远不会第 81 抽）。
- 史诗和稀有的绝对概率不变，软保底时挤掉的是普通。
- **二档保底**：每 10 抽内至少一件史诗或以上（连续 9 抽都没有史诗或以上，第 10 抽若不是传说就必是史诗）。
- 保底计数按「保底组」分：常驻池一组（`std`），所有限定池共用一组（`limited`，换季延续，原神式）。抽传说两档计数都清零，抽史诗清二档计数。

### 3.3 综合概率（算上保底后的长期实际概率，菜单里公示）

用马尔可夫链（状态 = 传说计数 × 史诗计数，800 个状态）精确求稳态，插件启动时算、菜单 / `/gacha rates` 显示同一组数：

| 品质 | 综合概率 | 说明 |
|------|---------|------|
| 传说 | **1.832%**（平均 54.6 抽一件） | 60 抽内出的占 30.3%；走到第 80 抽硬保底的概率 0.00079% |
| 史诗 | **11.69%** | 含二档保底 |
| 稀有 | **13.29%** | 被二档保底挤掉一部分 |
| 普通 | **73.19%** | |

单件概率 = 品质综合概率 × 该件在品质内的份额。传说有「不连出同一件」规则，份额不是简单的权重比，按物品马尔可夫链（i→j 概率 = wⱼ / (W − wᵢ)）的稳态算，菜单逐件公示。

### 3.4 明日方舟式规则

- **不连出同一件传说**：同一池里，这次传说一定不是上次那件（池里只有一件传说时不限制）。
- **火花（定轨兑换）**：每个池单独计火花，每抽 +1；满 200 点可在该池**任选一件没有的外观**（扣 200）。限定池结束后剩的火花折光屑（§2.2）。

## 4. 卡池

### 4.1 常驻 · 余烬星愿（`standard`，保底组 `std`，一直开）

| 品质 | 外观（种类） |
|------|-------------|
| 传说 ×4 | 余烬灯灵（宠物）· 霜晶灵（宠物）· 凤羽光环（光环）· 烬火领主（扭蛋称号） |

| 普通 ×8 | 聊天徽记 ✿ ☘ ♪ ☀ ✧ ☾ ❀ ♠ |

CoreRpg 外观商店的 ♛ 王冠（2 万币）不进池，留作商店的最高价件。CoreRpg 的件已经在商店买过的，抽到就是重复（返光屑）。

### 4.2 限定 · 国庆烟火盛典（`gq26`，保底组 `limited`）

- 时间：**2026-10-03 00:00 → 2026-10-08 00:00 CST**，和 `plugins/CoreRpg/ember-v1-festival.yml` 的「烟火庙会」同一窗口。
- 传说：**锦鲤灵**（宠物，权重 35）、**盛世烟火**（光环，权重 35）、常驻 4 件传说各 7.5 → 权重上 70% 是限定；「不连出同一件」会让两件限定互相挡掉一部分，实际稳态份额是 **62.1%**（锦鲤灵 / 盛世烟火各 31.06%，单件综合 0.569%；常驻传说各 9.47%，单件 0.174%），菜单逐件公示的就是这组数。
- 史诗：**满天星火**（烟火特效，权重 3）、**灯火阑珊**（扭蛋称号，权重 3）、常驻 8 件史诗各 1。
- 稀有：**灯会流光**（光环，权重 3）、常驻 12 件稀有各 1。
- 普通：**✸ 烟花徽记**（权重 2）、常驻 8 个徽记各 1。
- **结束后**：池关闭，6 件限定外观转入常驻池（权重 1），之后能在常驻池抽到、也能用光屑换。火花折光屑。保底计数留在 `limited` 组给下一个限定池。

### 4.3 每季一个主题池

下一个主题池 = 在 `gacha.yml` 的 `banners:` 里加一节（`type: limited`、`start` / `end`、`retire_to: standard`、物品表），`/gacha admin reload` 生效，不用改代码。

## 6. 数据与事务（MySQL，和 CoreRpg 同库 `ember`）

连接信息运行时从 `plugins/CoreRpg/config.yml` 的 `mysql:` 节读（CoreGacha 自己的配置里不存密码，日志只打 host/port/库名，启动成功打印 `[CoreGacha] MySQL connected`）。

| 表 | 内容 |
|----|------|
| `gacha_wallet` | uuid、名字、券、光屑、见面礼标记 |
| `gacha_pity` | uuid × 保底组：传说计数、史诗计数 |
| `gacha_banner_state` | uuid × 池：火花、上一件传说、累计抽数、火花已折算标记 |
| `gacha_owned` | uuid × 外观：来源（pull / craft / spark / admin）、时间 |
| `gacha_wear` | uuid × 种类：穿戴中的外观 |
| `gacha_pull` | **审计**：每一抽一行 —— 自增 pull id、批次 id、uuid、名字、池、保底组、批内序号、品质、外观、是否重复、返还光屑、传说计数前 / 后、史诗计数前 / 后、火花后、触发规则（base / soft / hard / tier2）、状态、时间（毫秒） |
| `gacha_ledger` | 券 / 光屑的每笔变动（来源、关联批次），含回滚记录 |
| `gacha_daily` | uuid × 日 × 键：今日抽数、今日已发的来源、换券数、活跃分钟 |

**一次抽卡 = 一个事务**（单线程 DB 执行器，外加 `SELECT … FOR UPDATE`）：

1. 锁钱包、保底、池状态；检查券和今日上限。
2. 用引擎抽 N 次（同一批里第二次抽到同一件就算重复）。
3. 扣券、加光屑、写保底 / 火花 / 拥有 / 审计 / 账本 / 今日抽数 —— 都在这个事务里。
4. 需要发 CoreRpg 外观的，事务还没提交时切到主线程发（发之前再查一次是否已拥有）。
5. 主线程发成功 → 提交。任何一步失败 → **回滚**（券没扣、保底没动），已发的 CoreRpg 外观撤回，另记一条 `pull_rolled_back` 账本行，告诉玩家「已退还」。提交本身失败也撤回 CoreRpg 外观。

兑换券（扣 CoreRpg 币 / 徽）是两边各一步：主线程先扣币，再写券；写券失败把币加回去（补偿）。

## 7. 命令

| 命令 | 说明 |
|------|------|
| `/gacha` | 打开扭蛋主页（TrMenu `ember_gacha`） |
| `/gacha pull <池> <1\|10>` | 抽卡（播放开箱动画，再开结果页） |
| `/gacha history` | 最近 100 抽（菜单页） |
| `/gacha rates <池>` | 概率公示页（含综合概率、单件概率） |
| `/gacha shop` · `/gacha craft <外观> [confirm]` | 光屑兑换页 / 兑换 |
| `/gacha spark <池> [外观]` | 火花兑换 |
| `/gacha exchange <coin\|badge> [张数]` | 余烬币 / 余烬徽换券 |
| `/gacha wear [外观\|off <种类>]` · `/gacha fx` · `/gacha redeem` | 穿戴 / 放烟火特效 / 实物券存入 |
| `/gacha admin reload` | 重读两份配置、重算公示概率 |
| `/gacha admin give-tickets <玩家> <n>` | 发券（记账本 `admin`） |
| `/gacha admin give-shards <玩家> <n>` | 发光屑（补偿 / 测试，记账本 `admin_shards`） |
| `/gacha admin inspect <玩家>` | 钱包、保底、火花、拥有数、最近 5 抽 |
| `/gacha admin simulate <池> <n>` | 用真实引擎离线跑 n 抽，对比公示概率（不写库） |

权限：`coregacha.use`（默认所有人）、`coregacha.admin`（op）。

## 8. 菜单（TrMenu）

- `ember_gacha`：两个池（常驻 / 国庆限定，限定显示剩余时间）、各自的单抽 / 十连、券 / 光屑 / 今日抽数 / 保底进度 / 火花、概率、记录、光屑兑换、换券、我的外观。
- `ember_gacha_rates`：当前查看的池：四档基础 / 综合概率、保底说明、逐件单件概率。
- `ember_gacha_history`：最近 100 抽（4 格 × 25 行）。
- `ember_gacha_shop`：光屑兑换（逐件价格、已拥有标记）。
- `ember_gacha_reveal`：结果页，10 格按品质上色（金 / 紫 / 蓝 / 灰），新 / 重复 + 光屑。
- 开箱动画（插件做）：约 2 秒的标题帧（✦ 依次亮起，颜色跟这一批最高品质走 —— 原神式「流星颜色」）+ 逐帧升调音效，传说额外一声 `ENTITY_PLAYER_LEVELUP` 和烟花粒子；然后打开结果页。
- 主菜单 `ember_hub` 第 4 排加「外观扭蛋」入口。

## 9. 验证

- 模拟器在插件里（`town.sunshine.coregacha.sim.GachaSim`，读同一份 `gacha.yml`、跑真实引擎），100 万抽报告放 `docs/tests/TEST-gacha-sim-2026-10-04.md`：观测传说率对公示综合率（±3σ）、各档率、最大连续无传说 ≤ 80、二档最大间隔 ≤ 10、无连续同一传说、限定份额、光屑产出（每抽光屑、凑齐全池要多少抽、光屑换传说折合多少抽）。
- 单元测试（`mvn package` 会跑）：保底边界、二档保底、不连出、火花、光屑、马尔可夫与解析值一致。
- 实机冒烟：新机器人 FreshG01 起；发券、单抽、十连、查库、CoreRpg 外观到账、记录页。

## 10. 不做 / 已知限制

- 不做付费、不做抽卡排行、不做交易（D73）。
- 「名字后的扭蛋称号」只在聊天显示（头顶名牌归 CoreRpg 的计分板队伍管，不去抢）。
- CoreRpg 没有发外观的控制台命令，CoreGacha 通过 CoreRpg 的公开 Java 接口（`CoreRpgPlugin#getDataStore()` → `PlayerData` 计数器，反射调用、主线程）写 `p2_cosbuy_<id>`，等同商店购买；CoreRpg 源码不改。CoreRpg 改了计数器命名就会发放失败 → 整批回滚退券（不会白扣）。
