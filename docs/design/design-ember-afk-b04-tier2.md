## 2. 现网事实（调研 · 本稿未改）

| 项 | 现网 / 证据 |
|----|-------------|
| 配置 | `afk_caps.enabled` · `over_chance: 0.25` · **无** `over_chance_2`；shard 日顶 **150** |
| 逻辑 | `afkCapped`：`c < cap \|\| random < over` 才出货并 `addPeriodCount`；达顶一句灰字 |
| 文档债 | softcap 批 **A 标定**；STATUS 明示禁宣称「封死通胀」 |

| 用户口径 | **否决**墙钟 2h 实挂；基线与日后对照均走 **短样→外推** |

**解读：**

3. 算数优先：用已落基线反推二档后 2h 期望，再决定是否开经济。

### 方案 A · 钉死表（批准后才可施工）

#### A1 · 配置意图（示意键名 · 插件可微调同义）

```yaml
afk_caps:
  over_chance: 0.25          # 不变
  over_chance_2: 0.08        # 新 · 钉死（落在 softcap 0.05～0.10 中位偏松）
  # 触发：当该 item 的当日 periodCount >= 2 * cap 时用 over_chance_2
  # （等价「超顶后再成功计入约 1×cap」；不另开分钟字段）
```

| 阶段 | 条件 | 掉率乘子 | ④ shard/h 期望（沿用基线 780） |
|------|------|----------|-------------------------------|
| 满速 | `count < cap` | **1.0** | ~780 |
| 一档 | `cap ≤ count < 2×cap` | **0.25** | ~195 |
| 二档 | `count ≥ 2×cap` | **0.08** | ~62.4 |

击杀币超顶分支（现读同一 `over_chance`）须**同逻辑**切二档，避免材料降、币不降。

#### A2 · ④ 2h 期望对照（短样外推 · 非实挂）

| 口径 | 满速 | 一档段 | 二档段 | **2h 合计 shard** | vs 日顶 150 |
|------|------|--------|--------|-------------------|-------------|
| **现网（仅 0.25）** | ~12 min → 150 | 余 ~108 min ×195/h | — | **~490～501** | **≈3.3×** |
| **批 A 后** | ~12 min → 150 | 至 2×cap：约再 **~45 min**（150 次成功 ÷0.25 ÷13.3/min）→ ~146 | 余 ~63 min ×62.4/h → ~66 | **~360～365** | **≈2.4×** |

骨尘 / 核心：同触发同乘子；核心满速更快触顶，二档更早，长挂肥度降幅同向（STATUS 写一行即可，不强制分表）。

#### A3 · 玩家可见（零指令）

- 一档：沿用现句（掉率降为 25%…）。  
- 二档：追加一句短提示，例：`§8[余烬] 挂机收益再降，建议去打日常/周本。`（**不**教 `/corerpg` `/mvtp`）。  
- 菜单 lore **可不改**（挂机庭沿用即可）。

#### A4 · 验收口径（批准施工后 · **短样外推**）

1. 配置出现明确二档字段；回滚=删字段或 `over_chance_2` 回退等价一档。  
2. **禁止**墙钟 ≥2h 实挂；用与基线同构：**数分钟 kills/min** + 上表分段公式 → STATUS 对照表。  
3. 抽检：`count` 在 `[cap, 2×cap)` 时期望出货率 ≈0.25；`≥2×cap` ≈0.08（二项波动须注明样本）。  
4. 跨层合并三项回归（`STATUS-afk-caps`：合并 / 文案 / 超限降率）。  
5. **禁止**宣称「绝对零通胀」；对外改为「双软顶，长挂显著低于满速」。
