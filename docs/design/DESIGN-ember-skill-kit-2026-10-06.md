## 0. 给服主的话（一页看懂）

**结论先说：** 研究稿里"4 个按键各自独立冷却"那版**过不了数值关**——每多一个白给的按键，低操作玩家（躲招 0.3）的通关率就涨 5～17 个百分点、杂兵房快 8～18%，这就是"新的永久强度"，违反硬限。所以 S0 把结构改了：

- **新按键不是"多给一招"，而是"同一份能量换个用法"。** 烬斩的 8 秒冷却当成一份"余烬充能"：按 F 放烬斩，**或者**按 潜行 + F 放副招，二选一。玩家每 8 秒要做一次真正的决定，而总伤害预算不变。这个做法参考魔兽 1.12 萨满的三种震击共用冷却。
- **能过关、可以开工（S1）的：**
  1. **烬斩三种形状（符文）**：扇形（现在）/ 直线穿刺 / 原地环斩，Q04 首通解锁，出本免费换。42 格全部 ±0。
  2. **副招·烬突**（潜行 + F，Q02 首通解锁）：花掉这一次烬斩充能，向前冲 4 格，穿过的最多 3 个敌人各吃 1.5B（首领 ×0.5）。伤害和烬斩一样，**多的是位移**；模拟里从不比烬斩强（最多弱 3.9 个百分点，只在一格），所以是纯侧移。
  3. **身法·火痕步**（焚烬专用，Q05 首通解锁，替换踏步）：踏步落点点燃 1 个敌人，用套装同系数。27 格全部在 ±2 内（平均 0.17）。
- **过不了、先不做的：** 守招（守墓壁垒 / 破势，5 种做法都试了）、副招·灰印、副招·聚火。原因是同一个：要么白送太多（低操作格 +8～+17），要么代价太大玩家永远不会用（"择优"收益 0）。守招需要换一个思路再做一轮（§4），不硬上。

**这样改完以后：** 新手 Q01 只有 F + 潜行 Q；Q02 首通开 潜行 + F（烬突），Q04 首通开烬斩形状，Q05 首通开身法变体。从 Q01 到 Q05 每两张图左右多一个"手上能感觉到"的东西，而且每 8 秒都要选"砍一刀还是冲过去"。

## 1. 模拟怎么做的

**格子：** 和签名传奇（D174）完全同一套：7 张图 × 首通前（r）/ 挑战（c）× 躲招 0.3 / 0.5 / 0.7 = 42 格，种子 7 和 11，每格每种子 1500 局，三套装各跑一遍。**可达格：** 某招由 Mk 首通解锁，就只看 M(k+1) 起的 r 格和全部 c 格。

**过关线（沿用 D174 §8）：** 目标是每个可达格通关率都在基线 ±2 个百分点内（✅）；硬线"在范围内"= 平均 |Δ| ≤ 1 且没有一格超过 ±3（🟡）；否则 ❌。另外列出用时、杂兵房、首领战、受伤的平均变化，和"主动份额"（烬斩 + 副招伤害 / 全部伤害；基线约 14.5%～16.6%，比研究稿手算的 10% 高，因为杂兵房烬斩一次打 3 个）。

**"择优"列：** 有些招是可选的（共享充能的招，玩家觉得不划算就不按）。择优 = 每格取 max(0, Δ)，表示"会用的人最多能多赚多少"。可选招要求择优也在线内；同时择优 ≈ 0 说明这招**永远不值得按**，那也算设计失败。

**模型（`p1sim.py` 新键，全部可选，不带键 = 今天）：**

| 招 | 键 | 机器人怎么用 |
|---|---|---|
| 守墓壁垒 | `kit_guard_cd / secs / red`；`kit_q_shared` + `kit_q_keep`（共享身法冷却，期间预警加成只剩 keep 倍）；`kit_guard_charge`（花烬斩充能） | 首领预警招落下时冷却好就按（最坏情况，X2）；期间所有受伤 −red，不能普攻 |
| 破势 | `kit_int_cd / p`；`kit_int_charge` | 同上；成功率 p 时整招取消（不触发落空 / 躲招效果）；破招（D193）上不能用（X3） |
| 聚火 | `kit_gather_cd / plus / secs / mult` | 杂兵房 ≥ 3 只时放；窗口内烬斩 / 烬爆多抓 plus 个，代价是多 1 个近战贴身 |
| 烬突 | `kit_dash_cd / mult / n / boss` | 非首领 ≥ 2 只时放 |
| 灰印 | `kit_mark_cd / delay / boss / mult` | 前排目标下一次攻击推迟 delay 秒（缓慢 I 的近似） |
| 火痕步 | `kit_step_cd / n / cost` | 焚烬时冷却好就用，点燃前 n 个 |
| 共享充能 | `kit_sec_shared` | 副招花掉这一次烬斩，烬斩重新等 8 秒 |
| 烬斩符文 | 复用 L07 / L09 的 `skill_var / skill_cap / skill_plus` | 同签名 |

## 2. 五轮结果（摘要；完整表见 out 文件）

### 第 1 轮 · 各自独立冷却（研究稿原方案）→ 全部 ❌（符文除外）

| 候选 | 判定 | 最高 / 最低 Δpp | 平均 |Δ| | 杂兵房 / 首领用时 |
|---|---|---|---|---|
| 守墓壁垒 cd18 −40% | ❌ | +8.1～+13.8 / −1.5 | 1.6～2.4 | 0 / +5～6% |
| 守墓壁垒 cd30 −30%（最温和） | ❌ | +5.3～+9.9 / −1.3 | 1.25～1.78 | 0 / +4% |
| 破势 cd30 / cd40 | ❌ | +5.8～+10.8 | 1.85～2.11 | — |
| 聚火 cd12 +2 | ❌ | +16～+18 | 2.9～4.9 | **−12～−18%** |
| 烬突 cd12 0.5B×3 | ❌ | +14.6～+42.8 | 3.4～4.6 | −9～−10% |
| 灰印 cd10 推迟 0.5 s | ❌（接近） | +3.7～+4.9 | 0.77～1.09 | 0 |
| 火痕步（额外耗时 0.5 拍） | ❌ | +6.9 / −5.9 | 1.73 | +2.8% |
| 烬斩符文 直线 / 环斩 | ✅ | 0 | 0 | 0 |

**读法：** 所有"白给"的招都把低操作格（d0.3）和临界格（基线通关 15%～50% 的格）往上推，这正是 D174 要防的东西。冷却从 18 秒拉到 30 秒几乎没用：起作用的是"首领最重那一下被挡住"，一场里一次就够。

### 第 2 轮 · 共享冷却、全额代价 → 大多"永远不值得按"

副招花烬斩充能（`kit_sec_shared`），守招花身法冷却、期间预警加成全没（`kit_q_shared`）。

- 守墓壁垒 / 破势：一直按的话通关率 −23～−34，**择优 0**——比踏步差太多，没人会用。
- 聚火：杂兵房 +22～+37%（每次都拿烬斩去换），择优 0。
- 灰印：首领 +15～+20%，择优在部分格 +2.6～+16.9（只在少数格划算，而且划算的时候很划算）→ ❌。
- **烬突 1.5B×3（= 烬斩伤害）：✅ / 35 of 36 / 34 of 36，平均 |Δ| 0.10～0.19，最低 −3.9，择优 0。** 唯一过线的副招：伤害和烬斩一样，只多一个位移。

### 第 3 轮 · 往"对半换"调

- 守墓壁垒共享身法、保留 50% / 75% 预警加成：平均 |Δ| 1.4～3.4，两头都超（最低 −16、最高 +19）❌。
- 破势同上：❌（最好的 sustain 1.02）。
- 灰印带 1.0B / 1.5B 单体伤害：择优 1.5～2.2 ❌。
- 聚火带 1.0B 脉冲：杂兵房仍 +1.4～+3.7%（模型里有"连放"问题，第 4 轮修）❌。
- **火痕步 替换踏步、点 1 个、不额外耗时：✅ 27/27，平均 0.17，最高 +1.5。**

### 第 4 轮 · 守招花烬斩充能 + 聚火不连放

- 守招花烬斩充能：全部 0.00——机器人每次烬斩一好就放掉了，预警落下时充能几乎从来不在，等于没有这招（模型结论：这么做，玩家得刻意"留着"）。
- 聚火修正后（窗口内不再放）：杂兵房仍 +4～+17%，❌。拿一刀烬斩换"下一刀多抓 2 个"在 3 只一组的房间里不划算。

### 第 5 轮 · 守招花烬斩充能，首领战"留着充能等预警"

- 首领战不放烬斩、全留给守招：首领用时 +24～+37%，通关率最低 −17～−42，择优 0～1.42 ❌。

## 3. 定稿（S1 / S2 / S3 照这个做）

| 位 | 按键 | 招 | 解锁 | 数值（定稿） | S0 结果 |
|---|---|---|---|---|---|
| 主招 | F | 烬斩（扇形 100° / 3.5 格 / 最多 5） | 一开始 | 1.5B，8 秒，**这 8 秒是"余烬充能"** | 基线 |
| 主招符文 | F | 直线穿刺（= L07：最多 3）/ 原地环斩（= L09：3 格内最多 3） | Q04 首通 | 同 1.5B | ✅ 0.00 |
| 副招 | 潜行 + F | **烬突**：花掉这一次充能，向前冲 4 格（走踏步同一套碰撞 + 门控，C7），穿过的最多 3 个各 1.5B，首领 ×0.5 | Q02 首通 | 无独立冷却 | ✅ / 🟡 级（35/36、34/36，最差 −3.9 且只会更弱；择优 0） |
| 身法 | 潜行 + Q | 踏步（现行）/ **火痕步**（焚烬专用：落点点燃 1 个，套装同系数）/ **后撤步**（向后 4 格，无伤害） | 踏步一开始；变体 Q05 首通 | 14 秒（不变） | 火痕步 ✅ 0.17；后撤步在模型里与踏步相同（无伤害、躲招已在 dodge 里） |
| 守招 | Q | **暂缓**（§4） | — | — | 5 种做法全 ❌ |

**和研究稿相比改了什么：**

1. 副招**不**单独计冷却，而是花烬斩充能（WoW 1.12 萨满震击共用冷却的做法）。这是唯一能在"无新永久强度"下加按键的结构。
2. 副招候选只留烬突；灰印、聚火在这套结构下不是太强就是没人用，**删掉**，以后如果做就重新设计、重新过 S0。
3. 守招从 S1 撤下（研究稿 S1 原本先上守墓壁垒）。S1 改为：**输入分流（潜行 + F）+ 技能页 + 副招·烬突 + 烬斩三形状**。身法变体（火痕步 / 后撤步）放 S2。
4. 单按 Q 暂时不改（不取消扔刃），守招有了能过关的方案再说——这样 S1 也不用碰 X8（取消丢弃造成的物品同步）。

**签名传奇与符文（研究稿 §4.4 维持）：** 戴着 L07 / L09 / L13 时，签名形状覆盖符文形状，符文页显示"被 XX 覆盖"。签名 L08 / L11 / L14（烬斩点燃 / 护盾）对烬突**不生效**（它们写的是"烬斩命中时"），避免一份充能吃两份签名。

## 4. 守招 S0b（D212）— 仍全 ❌，建议搁置

S0 五轮之后按 §4 原提案又跑了四轮（`tools/p1sim/out-skillkit-s0b-r1-probe.md`～`r4.md`；模型新增 `kit_guard_defer` / `kit_guard_pay` / `kit_guard_heavy` / `kit_guard_nobusy` / `kit_guard_hp` / `kit_guard_lethal` / `kit_guard_pay_mult`，无键时仍逐位一致）。

### 4.1 试过的方向

| 方向 | 代表候选 | 结果 |
|---|---|---|
| 醉拳 defer（吸窗后原量摊还）+ 自有 CD | GDf18 / GDf30 | 不涨通关（常为负）；僵直代价让 always-press −3～−10；择优 ≈ 0～+3 → 要么白送要么没人按 |
| 醉拳 + 共享身法 | GDfS / GDfSk50 | 择优 0（永远不值得按）|
| 仅非轻招 −40%（与踏步分工） | GHv18 / GHv30 | d0.3 **+7～+16** ❌（"挡住最重一下"仍过强）|
| 仅非轻招 + 醉拳 | GHvDf18 / GHvDf24 / GHvDf1s | d0.3 上沿多 ≤+2；always-press 被僵直拉到 −4～−10；择优 +0.6～+2.5 |
| 一击醉拳 + 长 CD | **GHvDf0cd36**（最接近） | scorch / sustain 🟡；burst 因单格 −3.8 仍 ❌；sustain d0.3 **+2.8** 刚过 "≤~2" 目标 |
| 回敬税 1.15～1.25× | GHvDf0t15 / t25 | 择优 → 0（没人按）|
| HP / 濒死才按 | GHvDf0L* | sustain ✅，但 scorch 临界格 **+3.6** ❌ |

### 4.2 为什么中间带是空的

同一结构性矛盾（S0 已见）：**临界格里"活过首领最重一下"的价值极高**。

- 代价太轻（无僵直 / 短 CD / 只 defer 不减伤）→ 低操作格通关率 +3～+16。
- 代价太重（共享身法 / 回敬税 / 长僵直）→ 择优 0，玩家永远不按。
- 最接近的 GHvDf0cd36（仅非轻招、一击 defer、cd36、僵直 0.3s）在 n=1500 下仍不能三套装同时进 ✅/🟡，且 d0.3 上沿在 sustain 到 +2.8。

位移 / 站位价值 p1sim 没有，真人手感可能比表好一点——但**通关率预算**在离线模型里过不了，不能拿"手感"开例外。

### 4.3 裁决（D212）

- **不实现** CoreRpg 守招代码（单按 Q 仍不取消扔刃；X2 / X8 不动）。
- **建议搁置**；若以后重开，只在有**真人通关 / 死亡回放**后再定数值，不再扩离线候选。
- 技能组下一档仍是 S2：火痕步 / 后撤步（S0 已 ✅），与守招无关。

## 6. 模型改动与复现

- `p1sim.py`：新增 `kit_tele / kit_swing / kit_sec / kit_step / _sec_cost` 和 `KIT_KEYS`（S0b 另加 `kit_guard_defer` / `heavy` / `nobusy` / `hp` / `lethal` / `pay_mult`）；`Fight.hurt` / `Fight.segment` 只在 `st['mods']` 里有 `kit_*` 键时进入新分支；所有新随机数用按时间取种的独立 `Random`，不动躲招 / 暴击 / 刷怪流。
- **逐位一致检查：** 19 个基线 / 签名格子（含 L09 形状）新旧 `p1sim.py` 输出逐字节相同（每轮改模型后都复查）。
- `selfcheck.py`：新旧都是同样 2 条既有失败（Q06 / Q07 图鉴缺"预警 3.0 秒"字样；`signin.py:34` 直接读规则文件），与本次无关，没有新增失败。
- 复现（仓库根目录）：

```bash
NPROC=7 python3 tools/p1sim/skillkit.py run 1500 /tmp/sk/r1.pkl                 # 第 1 轮（独立冷却）
SK_ROUND=2 NPROC=7 python3 tools/p1sim/skillkit.py run 1500 /tmp/sk/r2.pkl      # 第 2～5 轮同理 SK_ROUND=3/4/5
SK_BEST=1 python3 tools/p1sim/skillkit.py report /tmp/sk/r2.pkl                 # 表 + 择优行
SK_ROUND=s0b4 NPROC=7 python3 tools/p1sim/skillkit.py run 1500 /tmp/sk/s0b-r4.pkl  # S0b 确认
```

**模型局限（如实写）：** 位移本身的价值（躲开站位类招、追远程）在 p1sim 里没有，所以烬突、后撤步只按伤害算——实际体验会比表上好一点；烬斩"打中几个"是固定的 3（`skill_hits`），所以三种形状在模拟里完全等价，真实差别要靠 S1 冒烟看手感。
