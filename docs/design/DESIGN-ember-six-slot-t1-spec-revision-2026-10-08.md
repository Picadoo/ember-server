## §1 根因改写 + 甲精工来源

### 1.1 更正：团本缺口不是「阶级 / 强化落后」

**我在 `ea7671f2` §0.4 写的归因（作废）：** 主因 = 投入顺序（资源先投护符、甲后补）；次因 = 新件 +0（换上新件瞬时强化落后）与 `arm_cap` 时间差；并把缺口折算成「约 1.6–2.1 级强化或 0.7 件阶」。这个折算只是等效换算，**没有逐人数据支撑**，方向错了。

**D316 逐人数据（G10，团本池 7 池 × 252 人，与 2 槽同种子配对）：**

| 指标 | T0' A（旧方案，甲自己养） | F（共鸣，D317 签） |
|------|--------------------------|--------------------|
| 甲比护符低阶件数（有效） | 0.00 | 0.00 |
| 有效强化差 | **−0.05**（几乎为 0） | 0（跟随） |
| 成色差（护符 − 甲，档） | **+1.79**（99.2% ≥ 1 档） | **+0.27**（中位 +0.25，p90 +0.75，≥1 档 9.5%） |
| 精工差（档） | **+2.21**（97.6% ≥ 1 档） | **+1.77**（中位 +2.00，p10 +0.75，p90 +2.50，≥1 档 87.7%） |
| 系数差（e+q+f 合计） | +0.1158 | +0.0462 |

| B（攻击）相对 2 槽 | p10 −4.44% | **0** |

**正确的机制（按 D316 / D317 签字原文）：** 阶级和强化在 T0' A 里**并不落后**；落后的是**成色 / 精工**。玩家手上那件旧甲强化过，新掉的同阶甲是 +0，打不过旧甲，于是高成色 / 高精工的新件一直穿不上去，成色 / 精工就长期停在早期水平。F 把阶 / 强化交给护符后，新件不再输在 +0 上，成色差从 +1.79 收到 +0.27；**剩下的差主要是精工约 1.77 档**，原因是甲没有任何锻造途径（E7：`forge_sink` 只给刃 / 护符精工→3），而护符在团本期基本靠工坊精工到 3。

`ea7671f2` 里**仍然成立**的部分：「新件 +0」是机制起点（但表现为成色 / 精工卡住，而不是强化差）；E（`follow: enh`）不够的判断结论对了，但 E 实际死在 G2 0.5 Q05 −3.0 [−3.3, −2.6]（资源前移），不是我写的理由。

**F 的门禁结果（这个精工差已经在里面）：** G8 团本 **9/9**（最差点估 R02 4 人 −1.6 [−2.7, −0.6]；R01 3 人 −1.2、R03 3 人 −1.4；队员 H 中位 322 / 320）；G2 21/21（最差 0.5 Q07 +0.6 [+0.4, +0.8]）；G3 −0.03 / −0.03；G4 最早 5.00 → 5.00、轮换 + 团本 −0.05、P2-1 −0.17；G5 0；G6 101,376 / 101,376 逐位；G8 挂机 21/21（最大 +0.4）。

### 1.2 精工差值多少（给选档用的量级）

- T3 护符 `h = 165`。一件甲的精工 +1 档 = `165 × 0.05 × 0.02` ≈ **+0.17 生命**；成色 +1 档 ≈ **+0.33 生命**。四件甲全部精工 +2 档 ≈ +1.3 生命（≈ 0.4% H）。
- 对照：护符精工 +1 档 = `165 × 0.80 × 0.02` ≈ +2.6 生命。**同一价钱下，甲的一档精工只值护符一档的 1/16。**
- 结论：精工差是**真实但很小**的差（H 中位 −0.46%），T0″ 带着它全过。是否补，主要看「换甲有没有意思」，不是看平衡。

### 1.4 顺带更正：甲分解白板

- D312 规格写「甲分解白板 × 0.1」，但 T0 / T0' / T0″ 的 F 配置**没有 `blank` 键**，p1sim 实际按 ×1.0 跑（`dismantle()` 默认 1.0）。
- `out-d246.md` 已证明白板产出在模型里**逐位无影响**（材料不是模型里的约束），所以门禁结果对 0.1 / 1.0 都成立；但**真实经济**里 ×1.0 会让胚的进账大致翻倍（每局多 1 件甲可分解），模型看不到这件事。
- **T1 口径：钉 ×0.1**（保守）。实现：甲分解按 `0.1 × 阶` 记入个人「胚零头」，满 1 出 1 胚，零头入库、审计可见；不改 `dismantleYield` 对刃 / 护符的结果。T1 报告须写明「白板经济模型未覆盖」。

## §2 换甲意义（玩家看得见、不打命令）

### 2.1 F 下玩家为什么换甲（文案只讲这三条）

1. **成色 / 精工**：同部位新甲成色或精工更高 → 生命略涨。数字小（一档 +0.2~0.3 生命），菜单**照实显示**，不放大。
2. **族**：为 Stage 2 四件套做准备（只看甲**自己的族 + 自己的掉落阶**）。Stage 1 只显示进度并标「后续开放」，不承诺数值。
3. **样子**：甲的材质随甲自己的掉落阶（T0 皮革 / T1 锁链 / T2 铁 / T3 钻石，族色由物品岗定）。传统 MC 的「穿上一套好看的甲」。

不做：战力分、排行榜、玩家可见 KPI、「推荐值」评分。（`EmberCompare` 已定原则：比整装，不出单一战力分。）

### 2.2 甲上显示什么（NI 模板 + CoreRpg 写 lore，与现有刃 / 护符同一路径）

## §3 旧档迁移（F 形式）

### 3.1 迁移不变量（改写 G6）

F 下生命 / 防御（Σw = 1）：

```
H0 = 20 + h[T_c] · ( g_c + Σ_a w_a · ((q_a + f_a) − (q_c + f_c)) ) + 等级项 + festHp
D  = D[T_c] + festDef              g_c = 1 + e_c + q_c + f_c（护符）
```

- **不变量：** 发给老号的 4 件甲 `q_a = q_c`、`f_a = f_c` ⇒ 括号里的差项**逐项为 0.0** ⇒ H0 / H / D / M / EHP 与 2 槽**逐位相等**；B 不受甲影响（G5）。这比 D312 的「4 件同 (T, e, q, f)」简单：**阶 / 强化不需要继承**（跟随），只继承成色 / 精工。
- **Java 必须按「护符 + 差项」写**（不能写成五项加权和）：同下标相减在浮点里精确为 0，才能保证逐位；这也是 T0″ G6 的写法（101,376 / 101,376）。
- **空甲位 = q0 f0 的甲**（p1sim 初始甲位就是 q0 f0 起步件）。所以没甲不会掉一大截，只会少 `w_a · h · (q_c + f_c)`（T3 护符 q2 f3 时每格约 1.2 生命，≈ 0.4% H）——这也是为什么必须给老号发**同成色 / 同精工**的甲。
- **没选护符 / 护符无效：** 甲贡献 0（与 2 槽无护符一致），不出现「没护符靠甲」。

- **时机：** 开关开后，玩家在枢纽首次登录 / 回城时执行；副本内、挂机中延后（D312 §2.2.6 保留）。
- **幂等：** `p1_six_mig=1` 写在发放成功之后；同一事务内「发放 uid 记账 + 置标记」；重复执行只读标记直接返回。

- **回滚：** 全局 = 开关切回 `false`（Loadout 回到 2 槽逐位，已发甲成为惰性物品，不丢不复制）；jar 备份；DB 行不删（D245 安全路径）。
